# turn-kernel

实验性的 TypeScript 回合制执行底座。游戏负责领域规则，内核负责输入版本检查、状态隔离、候选验证和一次提交。配套实验：[mindbug-lab](https://github.com/YuuinIH/mindbug-lab)。

## 运行

需要 Node.js 24+。

```sh
npm ci
npm run check
```

`npm run check` 包括严格类型检查、编译期非法组合反例和 Node 行为测试。没有运行时第三方依赖。

## 接口

游戏实现 `GameDefinition<State, Command, Fact>`：

- `parseState(unknown)`：解析结构并验证领域不变量。
- `parseCommand(unknown)`：解析外部输入。
- `decide(state, command)`：在隔离副本上计算候选状态与事实，或拒绝。

`createSession` / `restoreSession` 返回：

- `submit(unknown)`：接收 `{ sessionId, revision, command }`。
- `dispatch(command, revision)`：有类型的本地调用，仍走运行时检查。
- `view()`：完整状态的独立副本。
- `snapshot()`：包含格式版本、规则集、会话、版本号和状态的独立副本。

版本号每次成功提交增加一；拒绝不推进。规则抛错、候选校验失败或结果无法保存为 JSON 时，不提交任何状态。所有检查和复制完成后，才切换权威状态。事实仅随返回值交付，不构成持久事件日志。

## 安全范围

这是实验，不是“任意 TS 代码绝对安全”的证明。

- 游戏模块是可信代码，必须定义正确的领域约束；内核不知道精灵或印记是什么。测试中的第二领域夹具验证了精灵治疗和印记操作不混用。
- 规则处理的是可修改的**副本**，不是权威状态。当前尚未实现面向内容作者的受限操作能力层。`decide` 是可信游戏实现接口，不应直接向第三方技能脚本开放。
- 没有恶意代码沙箱、CPU/内存预算、进程隔离或外部副作用回滚。死循环不能由这个同步宿主中止。
- 原子性只涵盖单个内存会话的一次同步提交；没有数据库事务、跨进程并发或崩溃持久化。
- 快照校验结构和不变量，不验证历史真实性。快照只应由可信存储提供；一个伪造但满足全部约束的状态不一定会被拒绝。
- 会话 ID 由宿主确保唯一。会话/版本检查不是身份认证。完整视图与快照不能直接发送给有隐藏信息的游戏玩家。
- 只能从明确完成的提交位置恢复，不能恢复任意 TS 调用栈。

第一版故意没有事件总线、万能属性写入、动态注册表或预设回合顺序。未来的通用能力必须来自两个实际游戏的共同需求。
